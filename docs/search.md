# 検索の運用

`/search/` は [Pagefind](https://pagefind.app/) による静的サイト内検索。
インデックスは `astro build` の**後**に pagefind CLI が生成する。

```jsonc
// packages/site/package.json
"build": "astro build && pagefind --site dist"
```

このため **`pnpm dev` では検索が動かない**（`/pagefind/` がまだ無いため）。
確認は `pnpm build && pnpm preview` で行う。

## インデックスの単位は「記事ごとの薄いページ」

**Pagefind のインデックス単位はページで、1ページに `data-pagefind-body` が複数あっても1レコードに統合される。**
当初はアーカイブ（1ページ20記事）をインデックス対象にしていたが、それでは

- 件数が記事数でなくページ数になる（`Cloudflare` で26件＝該当ページ数。記事は43件）
- 結果タイトルが全て「アーカイブ」になる
- `data-pagefind-meta` もページ単位なので、**ページ内の最後の記事のURL**が全結果のリンク先になる

という状態だった（2026-08-16 実測）。

そこで `src/pages/a/[id].astro` で**記事1件につき1ページ**を生成し、そちらをインデックス対象にしている。

- 中身はタイトル・要約・ソース名・日付・タグと、原文へのリンクだけ（平均 834 バイト）
- `data-pagefind-meta="url[href]"` を原文リンクに付け、`/search/` の `processResult` で
  検索結果のリンク先を原文URLに差し替える。**利用者がこのページに来ることは通常ない**
- サイト内のどこからもリンクしていない

### 検索エンジンには載せない

薄いページには `<meta name="robots" content="noindex,nofollow">` を出している。

`robots.txt` の `Disallow` は使わない。クロールを止めるだけで URL 単体がインデックスされることがあり、
かつ `noindex` を読みに来られなくなるため逆効果になる。
**Pagefind は robots メタを見ない**（ビルド後の HTML を直接読む）ので、noindex にしても検索は効く。

### lang は ja に固定する

薄いページの `<html lang>` を記事ごとの言語にすると、Pagefind が ja/en の2インデックスを作る。
`/search/` は `lang="ja"` なので既定では ja しか引かず、**英語記事が検索から丸ごと落ちる**
（実測: `Cloudflare` が 43件中13件しか出なかった）。`PagefindUI` の `mergeIndex` で
en を併合する指定は効かなかったため、`lang="ja"` 固定の単一インデックスにしている。

トレードオフとして英語のステミングは効かない（`running` で `run` は引けない）。
技術記事の固有名詞検索が主用途なので許容している。

## 実測（2026-08-16）

| 項目 | 値 |
|---|---|
| ビルド | 3521ページ（うち薄いページ3053）を約4秒、Pagefind のインデックス生成が1.6〜5秒 |
| インデックス | 3053ページ・25,494語・1言語 |
| `dist` 合計 | 18.3 MB（うち薄いページ 2.4 MB、Pagefind 3.0 MB） |
| `Cloudflare` | 43件（該当記事数と一致）。リンク先は原文URL |
| `メルカリ` | 17件。リンク先は原文URL |

## 既知の非対称: 日本語のソース名は引けない

ソース名も索引に入っているが、**英語のソース名は引けるのに日本語のソース名は引けない**。

- `Cloudflare` の43件には、タイトル・要約に無く「The Cloudflare Blog」というソース名だけで一致した6件が含まれる
- 一方「メルカリ Engineering Blog」を持つ記事は約100件あるが、`メルカリ` の検索結果は17件で、
  いずれもタイトル・要約に「メルカリ」を含むもの。ソース名だけの記事は出てこない

Pagefind の日本語分かち書きの挙動によるものと見られる（未確定）。
結果として「メルカリ**について**の記事」が出て「メルカリ**が書いた**記事」は出ない状態で、
キュレーション用途としてはむしろ都合がよいが、意図して設計したものではない。
ソース別に見たい場合は `/sources/mercari-engineering/1/` を使う。
